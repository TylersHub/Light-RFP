Methodology

This report uses the public ESBD solicitation listing page as the entry point, then fetches each solicitation detail page to extract required fields such as title, solicitation ID, contact information, posting date, due date, classification, and attachment links.

Relevance is determined by weighted keyword and fuzzy matching against the vendor service categories from the take-home brief. Matches in solicitation titles and classification codes count more heavily than weaker description-only signals, while clearly unrelated terms such as software-only or legal-service signals are penalized.

This implementation favors a straightforward HTTP-first scraper because the required ESBD data is available in the server-rendered HTML. The main trade-off is that some additional relevance signals may live inside attached PDFs, which are linked here but not yet parsed in this MVP.
